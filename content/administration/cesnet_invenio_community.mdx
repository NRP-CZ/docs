# CESNET Invenio Community

The CESNET Invenio Community brings together people who develop and run repositories built on CESNET Invenio — a core repository system of the Czech National Repository Platform (NRP). It is a space for developers, operators, data curators and other repository roles from institutions across Czech academia.

The community works both ways: the CESNET Invenio development team passes on codebase updates and implementation recommendations, and members raise questions, share practical experience, propose new topics — and bring feedback that feeds into the system's roadmap.


## Meetings

* **CESNET Invenio Community meetings** take place on the **first Wednesday** of every month at **11:00**.

* Upcoming meetings are listed in the shared **calendar** available at the [EOSC RepoBuilders community page](https://www.eosc.cz/en/communities/repobuilders#kalendar_repobuilders).

*The calendar contains also the quarterly meetings of the broader [RepoBuilders community](https://docs.nrp.eosc.cz/en/docs/repo_admins/community/repobuilders) that cover topics spanning repository systems.*

### Meetings details & presentations

<details>
<summary><b>2026-11-04 — Deposition Workflows</b></summary>

First meeting of the new monthly CESNET Invenio Community series. The main topic is deposition workflows — how deposition works in CESNET Invenio today, where it gets stuck, and what to configure.

**Update & roadmap**

* CESNET Invenio 14 releases Q4 2026 (+18 months support)
* CESNET Invenio 12 support ends 31 Dec 2026
* CESNET Invenio 15 feature requests by 31 Dec 2026
* CCMM 2.0 ships with CESNET Invenio 15

**Deposition workflows**

* Rules governing a record's lifecycle; declared per community, at least one, one default; linked at creation.
* RDM = one fixed review flow; CESNET Invenio = each community can define its own curators, curation policy and workflows; permissions are set inside the workflow.
 Roles: owner, curator, member + custom via `configure_communities()` in `invenio.cfg`; per-state permissions; global + community role levels.
* Perun no longer integrated — import only, no sync; owner manages members in UI.
* Curation policy must be concrete and verifiable; feeds LLM checks (new in CESNET Invenio 14, needs an `ai.e-infra.cz` API key, advisory only).
* Individual submission needs the global submitter role (self-publish); direct publishing is API-only. Some decision-tree branches are not working yet.
* Custom workflows via `configure_workflows()`; advanced policies discouraged.
* Recommendation: prefer default components.
* Known issue: hardcoded "reader" role upstream vs. "member".

**Discussion**

* **Curation checks:** CESNET Invenio ships the LLM check; the rest (Invenio RDM / OARepo checks) must be implemented by the repository team — currently no user-friendly config UI, requires manual setup.
* **File uploads and transfer:** the UI uploads large files in parts automatically; a failed transfer can be re-uploaded after a network drop. File transfer methods `fetch` and `remote` must be enabled — `fetch` downloads a file from a URL into the instance (the record cannot be published until transfers complete), `remote` stores only a reference and redirects to the external URL. More information: [File transfer](URL_DOPLNIT).
* **NMA XSLT (2.0 → 1.1):** conversion runs on the NMA side, triggered by the 2.0 namespace in the OAI-PMH payload — not the repository's job. Conversion is not 100%; some information is lost.
* **OAI-PMH `ListMetadataFormats`:** the format name (`ccmm-xml`) is not decisive; the namespace URI / element name of the payload determines whether NMA treats it as CCMM 1.1.0, 2.0 or DataCite. The format name is a registration parameter.
* **Compound records (datasets):** implementation starts next week, targeted at CESNET Invenio 15.
